## 5. 遗留风险与「有意保留」项

### 5.1 明确不修、并说明理由

| 项 | 理由 |
|---|---|
| **工具链 pin 未切到 1.93.1** | `rust-toolchain.toml` pin 的是 `1.93.1`，但本机只装了 `1.93.1-x86_64-pc-windows-**msvc**`；实际 gnu 构建用 rolling `stable` = **rustc 1.99.1**。强切 1.93.1-gnu 需全新下载 + 全量重编译（约 26 分钟），且依赖树可能要求更高 rustc，有破坏已验证产物的风险。本轮改为**如实记录**：`BUILD_INFO.txt` 写入 rustc/toolchain，`build-gnu.sh` 注释说明覆盖原因。真要 pin 请单独排期并做一次干净构建验证。 |
| **上游源码里 11 处 `CapCut` 字样** | 位于 `batch_volume.rs`、`format.rs`、`keymap.rs`、`media_bin.rs`、`prefs.rs`、`studio/*` 等，内容是「the way CapCut draws / Q,W as in CapCut」这类**交互设计参考注释**，属于红线允许的 UX 参考、不是品牌标识或复制代码；改动会触发大面积重编译。予以保留，仅在主题配色命名处做了品牌统一。 |
| **AppPublisherURL / SupportURL 仍指向上游仓库** | AGPL 溯源署名需要，且本项目未发布过安装包，无自有支持站点。保留。 |
| **图标仍叫 `concat.ico`** | 资源文件真实存在，改名需同步 build.rs、iss、wxs、winresource；属纯命名整理，不影响运行。 |
| **`.cargo/config.toml` 仍是本机绝对路径** | Cargo 不解析 `target.*.linker` 的相对路径、也不支持 config 内环境变量插值；改成 PATH 名或环境变量会改变 fingerprint、需要一次全量重编（约 27 分钟）。本轮采取折中：在文件内补了「换机须知 + 等价环境变量覆盖写法」注释，实际值不动；`tools/build-gnu.sh` 是推荐入口。**第二轮更正**：此处原写「已用 `$PRJ` 动态拼出全部路径」不严谨——当时 `$PRJ` 本身仍是硬编码的 `D:/AiSof/…`；§7 已把 8 个脚本统一改为由脚本位置推导，并加「配置 linker 与推导值不一致时才覆盖」逻辑，本机实测 0 重编。 |

  80.2 MB exe + 7 个 FFmpeg DLL + 4 个 MinGW DLL + LICENSE / THIRD_PARTY_NOTICES /
  BUILD_INFO / RUNTIME-DEPENDENCIES / README / 启动器。无绝对路径，可整体搬移。
- 启动器把 PATH 收窄为「本目录 + Windows 自身」，`--version` / `--smoke` /
  `--whisper-cpu` 全部 RC=0。
- WiX 4.0.5 以 dotnet tool 装到 **`tools/wix/`**（`NUGET_PACKAGES` /
  `DOTNET_CLI_HOME` 都指向项目目录，未写 C 盘）。本机只有 .NET 6，WiX 7 需 .NET 8，
  故固定 4.0.5。
- `concat.wxs` 原用 `<Files Include="$(var.Stage)\**" />`，WiX 4.0.5 报
  `WIX0005: unexpected child element 'Files'`（放进 `Component` 里同样报错）→ 改为
  **显式 18 个 `<File>`**，并在 `tools/build-installer.ps1` 加「wxs 清单 vs stage
  目录」一致性守卫，防止以后新增 DLL 漏进安装包。
- `tools/build-installer.ps1`：先试编通过（假 stage，64 MB 测试 MSI），再用真 stage
  出正式 MSI，RC=0。Inno Setup 的 `setup.exe` 因本机无 `ISCC.exe` 跳过，脚本保留
  `-Inno` 参数；`concat.iss` 已同步 0.2.10 与自有 AppId。

### 8.6 冒烟、门禁与 CI

- `scripts/ci/smoke-windows.ps1` 本机只有 PowerShell 5.1、无 Visual Studio/dumpbin，
  原脚本（`#Requires -Version 7` + `ArgumentList` + `Kill($true)` +
  `EnvironmentVariables["PATH"]`）必然失败。本轮改造为**双版本兼容**：
  `Arguments` 字符串 + `try Kill($true)/Kill()` + 临时替换当前进程 PATH（子进程继承）、
  dumpbin 缺失时回退项目内 MinGW `objdump`，并补 `--whisper-cpu` 与 `-Bundle`
  默认值。实测 **RC=0**：扫描 12 个 PE 的导入表，三项干净 PATH 冒烟全过。
- `scripts/ci/verify-longcut.ps1` 由 11 项扩到 **12 项**，最终 **12 PASS / 0 FAIL / EXIT=0**。
- `.github/workflows/longcut-windows-gnu.yml` 对齐发布态：12 步，
  `LONGCUT_PROFILE_DIR=app`、`--profile app` 构建、app 便携包、门禁、
  clean-PATH smoke、WiX 4 安装、MSI 编译、便携包 + MSI 归档；PyYAML 解析通过。
- **CI 首跑的边界**：本工作区无 `.git` / 无 Actions 权限，GH-hosted runner 尚未实测。
  本机按 workflow 的顺序把其中可本地执行的步骤（build / stage / gate / smoke /
  wix / installer）**逐项实跑通过**，runner 专属步骤（checkout、rustup 安装、
  缓存、artifact 上传）只能等第一次 `workflow_dispatch`。此项如实记为 🟡。

### 8.7 本轮踩到的坑与解法

| 现象 | 根因 | 解法 |
|---|---|---|
| 连续两次 `os error 32 ... build-script-build (never executed)` | 360 主动防御短暂锁住新建的 build script exe，cargo 立刻执行撞锁 | 自动重试循环（最多 8 次，`-j 2`，间隔 6 s）；失败点从 portable-atomic → serde_core → rustversion 逐步推进，第 2 次成功 |
| fat LTO 极慢 / 内存 12.8 GB | 全依赖图作为单一 LLVM 单元优化 | 不改配置，实测推进（CPU 持续增长、`.lto.*.bc` 依次生成），最终 63m32s 完成；备选回退方案是把 `lto` 降为 thin |
| WiX `WIX0005` | 4.0.5 无 `<Files>` harvest 元素 | 改显式 `<File>` 清单 + 一致性守卫 |
| PS 5.1 多处 API 不兼容 | .NET Framework 与 .NET Core 差异 | 见 8.6 |
| 编辑器 backup 服务间歇超时 | 沙箱 `sandbox-center` 超时 | 对 `.wxs` / `.sh` / `.txt` 降级为 Python 原子替换；4 个 `.ps1` 最终仍由编辑器写入并复验 `ParseFile` 0 错 |
